Backend

Not used yet. Metadata is currently read straight from the Apple Music catalog, which needs no account and no key. These settings are reserved for the upcoming self-hosted backend transport.
Base URL of your self-hosted Apple Music proxy. It must expose the Apple Music catalog endpoints (/v1/catalog/{storefront}/...) and return the upstream JSON verbatim.
Sent as the X-Api-Key request header. Leave empty if the backend requires no authentication.

Catalog

Storefronts are tried in order until a match is found. The Apple Music language parameter follows the storefront (jp → ja-jp, us → en-us) unless overridden below.
Optional. Forces the Apple Music l parameter for every storefront. Leave empty to derive it from the storefront.

Requests

Edge length substituted into the Apple Music artwork URL template.

Cache

Stores responses on disk so the same track, album or artist is not looked up twice. Strongly recommended: a library scan would otherwise repeat the same album query once per track.
Kept shorter than the cache lifetime, since a track missing today may be added to the catalog tomorrow.
Upper bound on the memory the cache may use. Least recently used entries are dropped once it is reached, so a large library cannot grow it without limit.
Responses above this size stay in memory only. Search responses run to about 31 KB and are rarely repeated once an id is known, whereas id lookups are around 1.5 KB and repeat often — the default of 8 KB keeps the useful ones on disk and the bulky ones off it.

Cache maintenance

Expired entries are ignored on read but are only deleted by the Prune the Apple Music cache scheduled task, which runs weekly. Both actions can also be triggered here.
